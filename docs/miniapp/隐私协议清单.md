# 小程序隐私协议与接口声明清单

> 用途：每次新增/修改隐私相关能力时，照此表更新**代码**与**微信公众平台后台**两处。
> 权威规则：微信官方《用户隐私保护指引填写说明》——「隐私指引说明内容需与代码包内引用相关接口一致」，
> 提审时平台会核验，**不一致会被审核拦下**。

最后更新：2026-11-01（对应多用户改造 P2-5 + Ollama 接入）

---

## 一、本项目实际用到的隐私能力

代码位置：`miniprogram/`（排除 `data/`、`node_modules/`）

| # | 能力 | 触发的接口 | 代码位置 | 是否经第三方 |
|---|------|-----------|---------|------------|
| 1 | **语音识别（ASR）** | `WechatSI.getRecordRecognitionManager()` → 录音 | `speech/wechatSi.ts` | ✅ 微信同声传译插件 |
| 2 | **登录身份** | `wx.login()` → code → `code2Session` → openid | `utils/auth.ts` | ❌ 微信官方接口 |
| 3 | **运行时权限** | `wx.getSetting` / `wx.authorize` / `wx.openSetting`（`scope.record`） | `speech/wechatSi.ts`、`utils/privacy.ts` | ❌ 微信官方接口 |
| 4 | **发音评估（录音上传）** | 跟读后录音 mp3 上传 `/api/pronounce` → 本地 OpenPronounce 评测 | `pages/trainer/trainer.ts` | ❌ 仅部署方自建后端，**不出设备**，录音即评即弃不保存 |

**明确不使用**（不要在协议里声明，多声明会被驳回）：

- 位置、相册、摄像头、手机号、头像昵称、剪贴板
- `wx.getUserProfile` / `wx.getUserInfo`（头像昵称一律不取，昵称由服务端随机生成）

## 二、微信公众平台后台要填的内容

入口：**设置 → 服务内容声明 →《用户隐私保护指引》→ 更新**

### 第 1 节 · 开发者处理的信息

| 声明项 | 用途说明（可直接复制） |
|--------|---------------------|
| 录音 | 用于你按住说话时的语音识别，将你的语音转成文字发送给 AI 搭子。录音仅用于当次识别，不保存音频文件。 |
| 用户账号信息（OpenID） | 用于识别你的账号，使你只能看到自己的对话记录、词汇本与学习画像，不同用户之间互不可见。我们不获取你的微信昵称与头像。 |

### 第 2 节 · 第三方插件信息

| 字段 | 填写 |
|------|------|
| 插件名称 | 微信同声传译 |
| 插件提供方名称 | 腾讯 |

> 依据：`app.json` 的 `plugins.WechatSI`（provider `wx069ba97219f66d99`，腾讯官方）。
> **代码里声明了插件，隐私指引里就必须有对应条目**——这是审核核验点。

### 第 3 节 · 第三方服务商信息

| 服务商 | 说明 |
|--------|------|
| 微软（Microsoft Edge TTS） | 语音播报服务。仅发送待朗读的英文文本到微软语音合成端点，不含任何个人信息；生成的音频不保存。 |
| （Ollama 本地部署） | AI 对话由使用者自行部署的本地大模型（Ollama）完成，数据不经过任何第三方服务器。 |

> Ollama 是**自托管**的，通常不需要列为第三方服务商；但 Edge TTS 走微软公共端点，**必须声明**。

### 第 4-9 节

- 存储期限：实现处理目的所必需的最短时间
- 使用规则、对外提供、投诉方式、补充文档：按模板默认文案填

## 三、代码侧必须配套的两处

### 1. `app.json` 的 `permission`（运行时权限用途说明）

```json
"permission": {
  "scope.record": {
    "desc": "用于按住说话，把你说的话转成英文文字发给 AI 搭子"
  }
}
```

> ⚠️ **`app.json` 的 `permission` 不能替代后台的隐私协议声明**——
> 它只是运行时权限弹窗的用途文案，后台《用户隐私保护指引》是独立的、必须填的。

### 2. `app.json` 的 `__usePrivacyCheck__`

必须为 `true`（已有），否则隐私接口会被直接禁用。

## 四、两条入口的区别（容易踩坑）

| 入口 | 路径 | 影响范围 |
|------|------|---------|
| **入口 1** | 设置 → 服务内容声明 → 用户隐私保护指引 | 只影响**现网版本** |
| **入口 2** | 管理 → 版本管理 → 提交代码审核 → 信息填写页 | 只影响**提审版本** |

- 提审时平台会**自动拉取现网版本的隐私协议**作为开发版本的初始内容
- **若提审被拦，就是要在入口 2 改**
- 开发版本审核通过并发布后，该版本隐私协议会覆盖现网

## 五、常见故障与对应处理

| 现象 | 根因 | 处理 |
|------|------|------|
| **微信「授权设置」页里根本看不到麦克风项** | 后台协议**未声明「访问你的麦克风」** | 见下方专项，补声明后重新提审 |
| `wx.authorize` 报 `authorize:fail api scope is not declared in the privacy agreement`（或 `privacy permission is not declared`） | 同上：协议未声明该隐私类型 | 同上 |
| `wx.getSetting` 返回里没有 `scope.record`，但代码里确实声明了 `permission.scope.record` | `app.json` 的 permission **不能替代**后台隐私声明 | 同上 |
| 授权弹窗只显示「允许使用个人信息与权限使用记录」，没有具体项 | 后台协议里**只声明了 OpenID，麦克风项缺失** | 补声明麦克风，重新提交审核 |
| 调用录音接口报 `scope is not declared` | 后台协议未声明麦克风 | 同上 |
| `WechatSI` 插件调用失败 | ① 小程序后台未添加插件授权（设置 → 第三方设置 → 插件管理）<br>② 用了测试号/游客 AppID | 检查插件授权与 AppID 类型 |
| 录音报错 `-30001` | **录音接口出错**（官方定义），真机最常见是 Android 系统级麦克风权限未授予 | 手机设置 → 应用 → 微信 → 权限 → 麦克风 |
| 正式版不工作但测试版正常 | 未做隐私保护声明 | 按本文档补齐 |
| 提审被拦「隐私指引内容与代码不符」 | 后台声明与代码实际调用不一致 | 用本文档第一节核对 |

### 专项：录音不工作的两个不同原因（别搞混）

微信给的两个错误长得像，含义完全不同：

| 报错 | 含义 | 处理 |
|---|---|---|
| `api scope is not declared in the privacy agreement` | **后台未声明**该隐私类型 | 去公众平台补声明 |
| `privacy permission is not authorized` | **用户未同意**（或 resolve 传了 disagree） | 检查隐私弹窗实现，见下 |

> ⚠️ 本项目实际踩到的是**第二种**，但日志被截断成
> `authorize:fail privacy permission is not`，一度被误判成第一种，白查一轮。
> **记录错误信息时不要截断在 40 字符，至少留 100+。**

### 专项：自定义隐私弹窗的两个必做项

若采用自定义弹窗（注册了 `wx.onNeedPrivacyAuthorization`）：

1. 「同意」按钮**必须**是
   `<button id="agree-btn" open-type="agreePrivacyAuthorization" bindagreeprivacyauthorization="...">`，
   普通 `<view bind:tap>` 不行；
2. `resolve({ buttonId: 'agree-btn', event: 'agree' })` —— **`buttonId` 必填**。

漏任一项，微信就**不认这次同意**：之后所有隐私接口一律报 `not authorized`，
而且**界面毫无反应、不弹任何错误**，是极难排查的静默失败。

**本项目已改用官方弹窗模式**（不注册监听 + `wx.requirePrivacyAuthorize()`），
彻底绕开这两个坑。详见 `miniprogram/utils/privacy.ts` 文件头。

### 专项：麦克风声明的三个「看起来都做了但没生效」

这是本项目踩过的最深的一个坑，三条**同时成立**才算配好：

1. **`app.json` 的 `permission.scope.record`** —— 只是运行时权限弹窗的用途文案，**不等于**后台声明；
2. **后台《用户隐私保护指引》里要有「访问你的麦克风」这一项** —— 这是微信的硬校验点，
   缺了它：`wx.getSetting` 里不会出现 `scope.record`、微信「授权设置」页看不到麦克风、
   `wx.authorize` 直接报 `not declared in the privacy agreement`；
3. **声明必须审核通过** —— 提交后要等审核，官方明确说「审核通过后过一段时间再试」。

**判断口诀**：只要「授权设置里看不到麦克风」→ 一定是第 2 条没做，跟代码无关。


## 六、变更检查清单

改动隐私相关能力后，逐条确认：

- [ ] 代码里的接口调用已更新
- [ ] `app.json` 的 `permission` 用途文案已更新
- [ ] 后台《用户隐私保护指引》第 1 节（处理的信息）已更新
- [ ] 若新增插件 → 第 2 节已加条目
- [ ] 若新增外部服务端 → 第 3 节已加条目
- [ ] 提审时在**入口 2** 确认内容一致
- [ ] 审核通过后，手机端**清除小程序缓存**再测（残留的旧授权状态会干扰）
